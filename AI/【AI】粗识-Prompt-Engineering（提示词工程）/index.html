【AI】粗识 Prompt Engineering（提示词工程）

发表于 2026-06-01 分类于 AI 阅读次数： Valine：
本文字数： 7k 阅读时长 ≈ 26 分钟

概述

你有没有遇到过这种情况：明明给了 AI 一个问题，得到的回答却空泛、跑题、毫无用处？

这不是 AI 的问题，往往是提问方式的问题。

提示词工程（Prompt Engineering）是一门关于如何构造和精炼提示词的艺术和科学，目的是最大化 AI 模型的性能，让它产出更符合需求、高质量的输出。

简单来说，提示词工程是一种与 AI 高效沟通的技巧：

  • 提示词（Prompt）：输入给 AI 模型（如 GPT-4、Gemini 等 LLM）的指令、问题或文本输入。
  • 工程（Engineering）：设计、优化和改进输入文本的过程。

一句话记住： 提示词工程 = 降低模糊性，提升你与 AI 之间的对齐度。

为什么需要学习提示词工程？

收益 说明
提高准确性 减少 AI 跑题、答非所问
节省时间 一次到位，减少来回修改
解锁能力 复杂推理、角色扮演、格式输出需要特定技巧
降低成本 好的提示词意味着更少的 API 调用

一个直观的比较

方式 A（模糊）： 帮我写篇关于猫的文章。

作家会茫然——写什么风格？给谁看？多长？没有信息，只能泛泛而谈。

方式 B（明确）： 请你以轻松幽默的口吻，为养猫新手写一篇 800 字的文章，重点介绍如何选择第一只猫和接猫回家前三天的必备准备。包含三个小标题，结尾附上一个简洁的 checklist。

提示词工程，就是学习如何像方式 B 一样与 AI 沟通。

为什么提示词工程如此重要？

对普通用户：解锁 AI 的真正潜力

很多人觉得 AI 不好用、回答空泛，往往是因为使用了过于简单的提示词。学习提示词工程可以：

  • 获得更准确的答案：减少胡言乱语或答非所问
  • 提高工作效率：一次性得到结构完整、可直接使用的文案、代码、方案
  • 激发创造性应用：头脑风暴、模拟对话、风格转换等

对开发者：构建 AI 应用的基础

对于基于大语言模型开发应用（智能客服、写作助手、代码生成等）的开发者：

  • 模型的配置接口：通过系统提示定义 AI 助手的角色、行为准则和知识范围
  • 影响效果与成本：好的提示词能用更短交互、更低 API 成本获得更优结果

提示词的基本结构

三种消息角色

角色 比喻 作用
System（系统提示） 幕后导演 设定 AI 的身份、规则和行为准则，在对话开始前生效
User（用户） 演员搭档 你每次发出的消息，提出任务或问题
Assistant（助手） AI 演员 AI 的回复；也可预填内容，让 AI 从那里继续

System Prompt 的价值

System Prompt 是与 AI 协作中最被低估的工具。普通用户通常只用 User 消息提问，相当于每次都要重新介绍规矩；而 System Prompt 相当于一本「工作手册」——只需设定一次，AI 在整个对话中都会遵守。

了解 Token 与上下文窗口

什么是 Token？

AI 模型以 Token（词元） 为单位处理文本，而非以「字」或「词」：

  • 英文：1 个单词 ≈ 1–2 个 Token
  • 中文：1 个汉字 ≈ 1–2 个 Token（通常比英文消耗更多）
  • 标点、空格也各自占用 Token
  • 经验公式：1000 Token ≈ 750 个英文单词 ≈ 500 个中文汉字

上下文窗口：AI 的「工作记忆」

每个模型都有上下文窗口（Context Window），即一次对话中能处理的最大 Token 数。超过上限，模型会「忘记」最早的内容。

Token 意识对提示词设计的影响

场景 Token 建议
System Prompt 精炼优先，核心规则控制在 500 Token 以内
输入长文档 先摘要再输入，或使用 RAG 只传入相关片段
多轮对话 历史会累积消耗 Token，长对话要定期「重置」或压缩
API 开发 输入 + 输出都计费，输出通常比输入贵 2–3 倍

写作建议： 把最重要的指令放在提示词的开头或结尾。中间位置的内容在长上下文中容易被忽视——称为「迷失在中间（Lost in the Middle）」现象。

清晰直接地表达

这是性价比最高的一条技巧：写清楚你想要什么。

AI 没有读心术，指令越清晰，输出越精准。

模糊 vs 明确

模糊版 ❌ 明确版 ✅
翻译这段话。 将以下段落从英文翻译成正式的商务中文，保留专业术语，句式偏向书面语。
帮我写个方案。 请为新品发布会撰写社交媒体推广方案，面向 25-35 岁都市女性，包含微博、小红书两个平台，各 3 条文案，风格活泼有感染力。
总结一下。 请用 3 个要点总结以下文章的核心论点，每个要点不超过 30 字，用通俗易懂的语言表达。

让指令更清晰的 5 个技巧

1. 明确受众与语气

  • ❌ 解释一下什么是量子纠缠。
  • ✅ 用类比的方式，向从未接触过物理学的高中生解释量子纠缠。

2. 规定输出篇幅

  • ❌ 介绍一下北京。
  • ✅ 用不超过 200 字介绍北京，重点突出历史文化和旅游亮点。

3. 同时给出要和不要

4. 说明最终用途

5. 把复杂任务拆成步骤

记住： 清晰 ≠ 啰嗦。精准的指令可以很简短，关键是每个词都有意义、没有歧义。

为 AI 分配角色

给 AI 一个具体的角色身份，是提升回答质量最立竿见影的方法之一。

为什么角色设定有效？

AI 在训练中学习了大量不同领域专家的表达方式。设定角色相当于告诉 AI：「从哪个知识库里调取信息，用什么风格表达。」

要素 说明 示例

用 XML 标签分离数据与指令

当提示词里既有指令又有需要处理的数据时，把它们清晰分开非常重要。

为什么要分离？

如果指令和数据混在一起，AI 可能无法分辨哪些是你的指令、哪些是数据内容。这既会导致逻辑混乱，在开放应用中还存在安全风险 （即提示词注入攻击）。

XML 标签：最简单的解决方案

加了标签后，AI 会正确识别标签内内容只是待处理的数据。

多文档处理示例

常用标签一览

标签 适合包裹的内容
<article> 待分析的文档或文章
<user_input> 来自外部的、不完全可信的用户输入
<context> 背景信息、参考资料
<example> 示例内容
<question> 需要回答的具体问题
<data> 需要处理的数据

最佳实践： 标签名称要有实际含义。<contract> 比 <text> 更好——AI 能从标签名理解内容性质。

让 AI 逐步思考

对于复杂问题，直接要答案往往不如先思考再作答。

为什么先思考更准确？

语言模型每次只预测下一个词。直接要结论会「猜」结论；先把推理过程写出来，那些内容会成为生成结论的依据，准确率显著提升。

三种触发思维链的方式

方式 用法 适用场景
标签隔离 在 <thinking> 中推理，在 <answer> 中作答 需要程序化提取答案
一步一步 「请一步一步地思考，展示每一步的推导过程」 数学题、逻辑推理
先列论据 「请先分别列出支持和反对的理由，再给出综合判断」 主观判断题

实战示例：邮件优先级分类

重要陷阱： 一定要让 AI 先分析，再下结论。若先给结论再解释，它会为已有结论找理由，而非真正推理。顺序非常关键。

用示例教会 AI：少样本学习

有些效果很难用文字描述清楚（特定语气、格式风格），直接给例子比反复描述更有效——这叫少样本学习（Few-Shot Learning）。

示例的力量

好示例的三个标准

  1. 覆盖典型变体：分类任务每类都要有示例
  2. 格式完全统一：所有示例的输入/输出格式一致
  3. 质量高于数量：2-3 个精心设计的示例 > 10 个随便凑的

技巧组合使用

避免 AI 胡说八道（防幻觉）

幻觉（Hallucination） 指 AI 自信地输出错误、不存在或凭空捏造的信息。通过提示词设计可大幅降低发生率。

为什么 AI 会幻觉？

语言模型本质是预测最可能出现的词。不知道时，往往不会像人说「我不知道」，而是生成听起来合理的回答。

五种防幻觉策略

策略 做法
允许说不知道 System Prompt 中加入：不确定时请直接说明，不要猜测
限制信息来源 「只根据 <reference> 中的内容回答，资料不足则说明无法回答」
先找证据再给结论 先在 <evidence> 中找支持性原文，再在 <answer> 中作答
标注置信度 关键信息后标注（高/中/低置信度）
降低随机性 API 中将 temperature 设为 0，适合事实性任务

防幻觉 System Prompt 模板

高风险领域： 医疗、法律、财务等场景，必须提供权威参考文档，限制 AI 在文档范围内回答，并提示用户向专业人士核实。

提示词链（Prompt Chaining）

当任务过于复杂，单条提示词无法可靠完成时，可拆成多个子任务依次执行，前一步输出作为下一步输入。

为什么需要提示词链？

把所有要求塞进一个超长提示词会导致：

  • AI 容易遗漏子任务
  • 前后步骤逻辑相互干扰
  • 出错时难以定位
  • Token 消耗高、成本上升

提示词链分而治之，每一步可独立验证，整体可靠性大幅提升。

适合使用提示词链的场景

场景 链式拆分方式
长文档分析 第1步提取关键信息 → 第2步分析 → 第3步生成报告
代码生成 第1步梳理需求 → 第2步设计接口 → 第3步实现代码 → 第4步写测试
内容创作 第1步确定大纲 → 第2步逐节撰写 → 第3步润色修改
数据处理 第1步清洗数据 → 第2步分类标注 → 第3步汇总统计

完整示例：简历筛选流水线

开发者建议： 在每一步之间加入输出验证逻辑（JSON 格式、关键字段），异常时自动重试或切换备用提示词。

元提示（Meta-Prompting）

不知道如何写好提示词时，可以让 AI 帮你写或改进——这叫元提示。

三种元提示用法

用法 1：从零生成提示词

用法 2：诊断并改进现有提示词

用法 3：针对具体输出反向推导提示词

元提示的局限性

元提示不是万能的，需要注意：

  • AI 生成的提示词仍然需要你亲自测试，不能直接盲目使用
  • AI 不了解你的业务背景，生成的提示词可能缺少关键约束，需要补充
  • 把元提示和迭代优化结合使用效果最好：让 AI 起草第一版，然后基于测试结果继续人工调整

推荐工作流：遇到新的提示词需求时，先用元提示让 AI 生成一个初稿，理解它的结构设计思路，再按照本文的技巧做针对性强化，比从零开始手写效率高 3–5 倍。

迭代优化工作流

提示词工程需要：写 → 测试 → 分析 → 修改 → 再测试，循环迭代。

标准迭代流程

一个真实的迭代过程

轮次 提示词 问题/结果
第一轮 总结这篇文章。 结果太笼统，没有重点
第二轮 用三个要点总结这篇文章的核心论点。 要点只是原文复述，没有提炼
第三轮 假设你是中学老师，用通俗易懂的语言分三个部分总结主要观点，每部分举一个生活中的例子，每部分不超过 50 字。 结构清晰，语言易懂，有具体例子

测试提示词的关键问题

  • 它做了我要求的事吗？
  • 格式对吗？
  • 换不同输入还能稳定输出吗？
  • 边界情况（空输入、超长、错误格式）处理了吗？
  • 有没有不想要的内容出现？

提示词的版本管理

速查表：四要素框架

每次写提示词时，检查是否涵盖四个核心要素：

要素 问自己 示例
角色 AI 应该以什么身份回答？ 你是一位专业的……
指令 AI 具体要做什么？ 请分析/总结/生成/翻译……
背景 AI 需要知道什么前提信息？ 读者是……，用途是……
限制 有什么格式/长度/边界要求？ 不超过…字，以 JSON 输出，不要涉及……

各技巧适用场景一览

技巧 适合什么时候用 核心语句
角色设定 需要专业深度时 「你是一位有 X 年经验的……」
清晰指令 每次（永远需要） 「面向…，不超过…字，不要……」
Token 意识 长文档、API 开发、多轮对话 关键信息放开头/结尾，精简 System Prompt
XML 标签 提示词混合数据与指令时 用语义化标签包裹数据内容
格式模板 需要固定结构的输出时 直接给出带占位符的模板
思维链 推理、判断、分析类任务 「先在 <thinking> 中分析，再在 <answer> 中作答」
少样本示例 难以用文字描述的风格/格式 提供 2-3 个输入→输出的例子
防幻觉设计 事实性任务、高风险场景 「只使用提供的文档，不确定请说明」
提示词链 复杂多步骤任务、流水线开发 拆分子任务，前一步输出传入下一步
元提示 不知如何写提示词、需要快速起草 「帮我生成/改进以下提示词，说明设计理由」
五段式架构 构建完整的 AI 应用时 角色 + 数据 + 规则 + 格式 + 示例

发布前检查清单

  • 指令是否清晰无歧义？读给陌生人能听懂吗？
  • 数据和指令是否用 XML 标签分离？
  • 是否明确了输出格式和长度限制？
  • 对于推理类任务，是否要求了「先思考再回答」？
  • 是否提供了 2-3 个高质量的示例？
  • 是否允许 AI 说「我不知道」？
  • 是否在多种不同输入上做了测试？
  • 边界情况（空输入、异常输入）是否处理了？
  • 复杂任务是否考虑拆分为提示词链？
  • 关键指令是否放在提示词的开头或结尾位置？
  • 是否记录了当前版本号和修改日志？

总结

学习提示词工程，就是学习一种新型的结构化沟通能力。

你不需要是工程师，也不需要懂机器学习。AI 是能力极强但完全依赖指令的执行者——指令越清晰、越完整、越有结构，输出就越好。

三个行动建议：

  1. 从模仿开始——拿一个用过的提示词，对照四要素框架改写一遍，对比效果。
  2. 不断迭代——不要满足于第一次回答，每次问：怎么改能让它更好？
  3. 建立自己的工具箱——把工作中有效的提示词保存下来，形成个人生产力资产。
